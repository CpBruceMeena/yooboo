Uno-No-Mercy Issue Report
=========================

Date: 2026-05-16
Branch: fix/lobby-start-issue

Environment:
- Frontend: Next.js app on http://127.0.0.1:3000
- Backend: Socket.IO game server on http://127.0.0.1:3001
- Browser: camofox remote browser host running the app pages

Observed issues:
1. Lobby join/start button requires refresh in some cases
   - Fresh browser pages often fail to connect to the Socket.IO backend on first load.
   - The client logs show "Socket error: timeout" and "WebSocket connection ... failed: WebSocket is closed before the connection is established."
   - After a reload, the lobby joins successfully and the start button appears.
   - This is consistent with a transport fallback or connection timing problem.

2. Server package start path is wrong
   - `server/package.json` currently references `src/index.ts` but the actual entrypoint is `server/index.ts`.
   - This prevents `npm run start` from working correctly inside the `server` folder.

3. Game start is not always reflected immediately on startup
   - The host can emit `start_game`, but some browser clients may remain stuck in lobby if the socket connection is unstable.
   - This appears related to the initial connection phase rather than the game logic itself.

Repro steps:
1. Start backend server on port 3001
2. Start frontend on port 3000
3. Open a game page in the camofox browser and create a new room
4. Open a second browser page and join the same room as a second player
5. Observe that the second client often reports a socket timeout and remains stuck in lobby until reload
6. After reload, the second client connects and the lobby shows both players
7. Clicking "Start Game" may not immediately transition some clients if the socket is not fully established

Fixes being applied in this branch:
- `src/hooks/useWebRTC.ts`
  - remove forced `transports: ['websocket']` restriction so Socket.IO can use polling fallback if needed
  - queue `join_room` requests until the socket is actually connected
- `server/package.json`
  - fix `dev` and `start` entrypoints to use the correct `index.ts` path

Next steps:

- Complete a full E2E game run and verify that game rules are enforced correctly
- Add any additional bug docs if gameplay rule violations are found
